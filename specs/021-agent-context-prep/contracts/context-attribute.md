# Contracts: Agent Context Prep (`[context]`)

**Feature**: 021-agent-context-prep | **Date**: 2026-08-21

Four externally observable contracts. Code-level signatures live in
[implementation-detail.md](../implementation-detail.md).

## C1. Grammar (Runefile surface)

`AttrItem` gains one bare alternative — no arguments, no payload:

```text
AttrItem = ... | "context"    (* project-health hook injected into agent context *)
```

- `[context]` combines on one line with other attributes (`[context, private]`).
- `formatter.Format` round-trips it as `[context]` (default bare-attribute
  path; golden fixture `testdata/fmt/context-attr.{rune,fmt}`).
- Files not using the attribute parse and format byte-identically (NFR-001).

## C2. Static diagnostics (analyzer surface)

All with code `RUNE2007` (`CodeInvalidAttribute`), severity error, spans on
the offending attribute/parameter; surfaced identically by CLI and LSP:

| Misuse | Message shape |
|---|---|
| Second `[context]` task | `duplicate [context] task "b" (already declared on "a")` + related location on the first |
| `[context]` + `[confirm]` | `[context] task "a" cannot use [confirm]: the hook runs unattended` |
| Parameter without default | `parameter "p" of [context] task "a" must have a default: the hook is invoked with no arguments` |
| `agent` executor | `[context] task "a" cannot use the agent executor` |
| `[confirm]` anywhere in the hook's dep/post-hook closure | `dependency "clean" of [context] task "a" cannot use [confirm]: the hook runs unattended` |
| `agent` executor anywhere in the closure | `dependency "summarize" of [context] task "a" cannot use the agent executor` |

## C3. MCP surface (protocol-observable)

- Initialize result `instructions` = the gathered context text (masked,
  capped) when a hook exists; empty/absent otherwise. Same value on stdio
  and HTTP transports; computed once per server start.
- The hook task never appears in `tools/list`, independent of `[private]`.
- Embedder contract: `mcpserver.Options.Instructions string` — plain data,
  already masked by the caller; the package performs no processing on it.
- Tool set, schemas, annotations, and all other MCP behavior: unchanged.

## C4. Agent-executor prompt (provider-observable)

With a hook (text or degrade notice):

```text
## Project context (generated by Runefile [context] task)
<gathered text>

## Task
<task body, interpolated, unchanged>
```

Without a hook — or when the hook succeeds with empty stdout — the prompt is
byte-identical to the pre-feature prompt (no headers, no blank lines added).
Gathering happens per CLI invocation, before the provider starts; a hook
failure additionally writes one warning line to Rune's own stderr. An agent
task invoked *as an MCP tool* runs without the prefix (the session already
holds the context as instructions; this is also the anti-recursion guard).
